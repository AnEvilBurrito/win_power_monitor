wpm/ android UI STUDY 03 / POWER SPLIT BY DISPLAY STATE / SESSION SCREEN

DESIGN PROPOSAL

Screen off, screen on: what each state actually costs.

One new section on the Session screen, built from the components already in use — the energy grid, the coverage track, the data list, the attention note. All fixtures reconcile: the two buckets add up to the session totals, so the split can never quietly contradict the number above it.

Low-coverage note “Screen-off time is poorly sampled: 38m 00s of 4h 10m. Doze suspends polling in low-impact mode — high-resolution mode gives a reliable screen-off average.” Existing attention style (warning role, left rule). Trigger: coverage below 50% for either bucket, naming the offending bucket. Duration alone never triggers it — a 3-minute screen-on stretch at 96% coverage is a fine average, and its length is already in the sub-line. The doze sentence appears only for the screen-off bucket of a low-impact session.
Empty / legacy no screen-off time yet · discharge time not recorded · “Screen state is recorded from version 5 onward; earlier sessions were measured without it.” Zero observed seconds in a bucket is reported as absent, never as 0 mW. A session whose buckets are both empty but whose elapsed time is not is pre-v5 history: the note replaces any split rather than recomputing one from stored totals. A v5 session has real out-energy but no stored discharging time, so it reports no bucket average and says discharge time not recorded rather than reusing the mixed basis or claiming it only charged.
CSV column display_on Appended after the existing provenance columns: 1 on, 0 off, blank when the poll recorded no display state.
Invariant off + on + unknown = observed Session totals are unchanged by the feature: Battery out / in keep integrating both directions for the whole session, and the buckets' out-energy must add up to Battery out. Their averages are discharge-only, so they are a drain comparison and not a second session average. A mismatch in the energy sum is a bug, not a rounding choice.

Decisions taken (adjustable)

  1. Bucket metric: discharge-only average (outWh / dischargeSeconds). A magnitude average including charge was tried first and reported 5.28 W for an idle screen-off bucket that happened to be charging; the charger's output is not the phone's consumption. The drain-rate rows it required are gone, because the bucket number now is that rate.
  2. Bucket order: screen off first, matching the question people open the screen for.
  3. Sub-line content: discharging duration and discharged energy; charge never appears in a bucket line. The session's own Battery in total still reports it.
  4. Low-coverage threshold: 50% coverage, and the average still prints beside the note because it is real, just thin. An observed-duration floor was removed after a device report: 3m 20s of screen-on time at 96% coverage is not poorly sampled.
  5. Interval attribution: the interval is booked to the state of the sample that closes it, so a transition can misattribute at most one interval. Splitting exactly on broadcast timestamps remains a later refinement.
